# NyxD — план разработки

Этот документ разбивает реализацию NyxD на последовательные проверяемые этапы. Основной архитектурный источник проекта — [`ARCHITECTURE.md`](./ARCHITECTURE.md).

Главный принцип порядка разработки: сначала подтвердить работоспособность криптографического стека, затем строить вокруг него слой данных и пользовательский интерфейс.

## Этап 2. Проверка технических рисков

**Статус:** реализовано и проверено на Android-эмуляторе.

### Цель

Подтвердить работоспособность критического криптографического конвейера до начала полноценной разработки:

```text
пароль → NFKC → Argon2id → raw key → SQLCipher
```

### Задачи

- Проверить совместимость выбранных пакетов с используемой версией Flutter.
- Запустить Argon2id внутри отдельного Dart Isolate.
- Передать полученный 256-битный raw key в SQLCipher.
- Создать и открыть тестовую зашифрованную базу.
- Проверить успешное открытие с правильным паролем.
- Проверить отказ при неправильном пароле.
- Проверить закрытие и повторное открытие базы.
- Проверить debug- и release-сборки на реальном Android-устройстве.

### Результат

Минимальный технический прототип, подтверждающий совместимость Argon2id, Dart Isolates и SQLCipher.

Фактический стек прототипа: `cryptography` 2.9.x, `sqlite3` 3.x с native hook `source: sqlcipher`, `unorm_dart` 0.3.x. Интеграционный тест подтверждает открытие базы правильным raw key и отказ при неправильном ключе.

### Критерии готовности

- UI не блокируется во время деривации ключа.
- Правильный пароль стабильно открывает базу.
- Неправильный пароль не позволяет прочитать базу.
- Поведение совпадает в debug- и release-сборках.

## Этап 3. Криптографическое ядро

**Статус:** реализовано и проверено на Android-эмуляторе.

### Цель

Создать единый протестированный компонент управления зашифрованным хранилищем.

### Задачи

- Реализовать генерацию криптографически стойкой соли.
- Реализовать NFKC-нормализацию мастер-пароля.
- Реализовать деривацию 256-битного ключа через Argon2id.
- Реализовать калибровку параметров Argon2id на устройстве.
- Выполнять KDF только вне UI-потока.
- Хранить ключ только в `Uint8List`.
- Реализовать best-effort зануление ключа и временных буферов.
- Создать единый сервис заблокированного и разблокированного состояния.
- Исключить попадание пароля, ключа и содержимого базы в логи.

### Целевой API

- `createVault`
- `unlockVault`
- `lockVault`

### Результат

Изолированное криптографическое ядро с автоматическими тестами.

### Критерии готовности

- Создание, блокировка и повторная разблокировка хранилища работают стабильно.
- Параметры KDF сохраняются вместе с метаданными хранилища.
- Ключ зануляется после блокировки.
- Исключения не раскрывают секретные данные.

## Этап 4. Слой хранения

**Статус:** реализовано и проверено внутри SQLCipher на Android-эмуляторе.

### Цель

Реализовать работу с заметками поверх зашифрованной базы.

### Задачи

- Подключить SQLCipher к основному приложению.
- Создать таблицу `entries` согласно архитектуре.
- Добавить версионирование схемы и механизм миграций.
- Реализовать создание, чтение, изменение и удаление заметок.
- Реализовать soft delete, восстановление и окончательное удаление.
- Использовать транзакции для составных операций.
- Реализовать безопасную обработку ошибок базы.
- Вычислять заголовок из первой строки `content`.
- Реализовать парсинг и агрегацию `#тегов`.
- Реализовать поиск без персистентного FTS-индекса.

### Решение для первой версии

Корзина очищается только вручную. Автоматическое необратимое удаление можно добавить позднее как отдельную настраиваемую функцию.

### Результат

Полностью рабочее зашифрованное хранилище заметок без финального интерфейса.

Реализована схема версии 3 с транзакционными миграциями, CRUD-репозиторием, ручной корзиной, отдельной таблицей Unicode-тегов, фильтрацией и поиском по расшифрованным данным в памяти без FTS. Старые теги из текста переносятся в таблицу меток при миграции с версии 2.

### Критерии готовности

- Все CRUD-операции покрыты тестами.
- Удалённая заметка не отображается в основном списке.
- Заметку можно восстановить из корзины.
- Миграции схемы проверяются автоматическими тестами.

- Добавить явное предупреждение об отсутствии восстановления пароля.

## Этап 7. Защитное поведение Android

**Статус:** реализовано и проверено комплексным набором тестов на Android-эмуляторе.

### Цель

Привести приложение в соответствие с заявленной моделью угроз.

### Задачи

- Установить `android:allowBackup="false"`.
- Добавить правила исключения файлов из backup/data extraction.
- Хранить базу, соль и метаданные только во внутренней директории приложения.
- Включить `FLAG_SECURE`.
- Немедленно блокировать приложение при уходе в фон.
- Добавить таймер блокировки при бездействии.
- Перед очисткой ключа полностью закрывать соединения с базой.
- Обработать гонки между автосохранением, lifecycle-событиями и блокировкой.
- Проверить последовательности `inactive`, `paused`, `resumed` и `detached`.

### Результат

Приложение автоматически закрывает доступ к данным при потере фокуса или бездействии.

Реализованы блокировка при любом уходе приложения из состояния `resumed`, настраиваемый тайм-аут бездействия от 30 секунд до 5 минут (по умолчанию 40 секунд), запрет скриншотов и превью через `FLAG_SECURE`, а также запрет Android backup/data extraction. Итоговые настройки резервного копирования дополнительно проверены внутри release APK.

### Критерии готовности

- Содержимое не появляется на скриншотах и в превью недавних приложений.
- После ухода в фон требуется повторный ввод пароля.
- После тайм-аута бездействия база закрыта, а ключ очищен.
- Незавершённое сохранение не повреждает базу и не оставляет соединение открытым.

## Этап 8. Backup, импорт и перенос

**Статус:** реализовано и проверено на Android-эмуляторе на уровне зашифрованного хранилища; системные диалоги выбора файлов требуют ручной приёмки.

### Цель

Позволить пользователю переносить и восстанавливать данные без облачной инфраструктуры.

### Объём первой версии

- Полный backup — копия зашифрованной БД вместе с необходимыми метаданными.
- Восстановление полного backup — полная замена текущего хранилища после явного подтверждения.
- Экспорт отдельной заметки — UTF-8 Markdown.
- Импорт отдельной заметки — создание новой записи.

Слияние двух полных баз откладывается. Оно потребует стабильных глобальных идентификаторов, дедупликации, разрешения конфликтов и обработки удалённых записей.

### Задачи

- Определить контейнер полного backup и его версию формата.
- Обеспечить консистентный снимок базы перед копированием.
- Реализовать экспорт через системный выбор файла или директории.
- Реализовать проверку backup до замены текущего хранилища.
- Предупреждать о необратимой замене текущих данных.
- Реализовать атомарное восстановление с возможностью отката при ошибке.
- Реализовать импорт и экспорт отдельных Markdown-заметок.

### Результат

Данные можно безопасно перенести на другое устройство и восстановить без усложнения первой версии слиянием баз.

Реализован версионированный контейнер `.nyxd`, содержащий консистентный снимок уже зашифрованной SQLCipher-базы и необходимые метаданные Argon2id. Перед заменой текущего дневника копия открывается во временной директории указанным паролем и проходит миграции. Неверный пароль или повреждённый контейнер не изменяет текущую базу. Импорт Markdown создаёт новую заметку, экспорт выбранной заметки создаёт UTF-8 Markdown-файл.

### Критерии готовности

- Повреждённый или неверно зашифрованный backup не заменяет рабочую базу.
- При ошибке восстановления исходное хранилище остаётся доступным.
- Экспортируемая полная копия не содержит незашифрованного текста.

## Решения, принятые для MVP

- Корзина очищается только вручную.
- Восстановление полного backup заменяет текущую базу; слияние не входит в MVP.
- Отдельная заметка экспортируется в UTF-8 Markdown.
- Персистентный FTS-индекс не используется.
- Android Keystore, биометрическая разблокировка и duress password не используются. Безопасная биометрия потребует отдельной обёртки ключа, привязанной к `BiometricPrompt`, и не входит в текущий MVP.
- Дополнительное шифрование отдельных полей не применяется.
